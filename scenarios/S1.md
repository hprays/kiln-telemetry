# S1 · 수집 프로세스 중단

## 상황과 목표

가상 가마 6기가 각각 초당 10건씩 기록을 보내는 도중 첫 번째 수집 프로세스를 종료했다. 목표는 중단 확인 후 5초 이내 정상 조회를 관측하고, 최종 360건이 누락·중복 없이 DB에 남는지 확인하는 것이었다.

## 재현과 대응

| 한국 시간 | 1대 구성 | 2대 구성 |
|---|---|---|
| 11월 26일 00:09 | 00:09:06.520에 `kiln-1` 종료를 확인했다. 00:09:09.523에 센서 DB에서 186건이 전송 대기 중임을 확인했다. 00:09:09.524에 수집기를 다시 시작했다. | |
| 11월 26일 00:10 | | 00:10:00.515에 같은 수집기 종료를 확인했다. 중단 중 게이트웨이는 `kiln-2`로 요청을 전달했다. 00:10:03.527에 대기 기록 6건을 확인했고, 00:10:03.528에 종료한 수집기를 다시 시작했다. |

Terraform에서 `replicas`를 1에서 2로 올렸다. 추가 수집기 1개를 생성하고 게이트웨이의 백엔드 목록을 갱신했다. 두 시험에서 읽기 캐시는 0초, 전송 묶음은 최대 12건, 중단 유지 시간은 약 3초였다.

| 지표 | 1대 | 2대 |
|---|---:|---:|
| 중단 중 정상 조회 | 0/27 | 26/26 |
| 중단 확인 후 첫 정상 조회 | 4.368초 | 0.078초 |
| 기록 생성부터 확인까지 p95 | 4,133.250ms | 246.747ms |
| 최대 관측 대기열 | 252건 | 30건 |
| 최종 DB 누락 / 중복 | 0 / 0 | 0 / 0 |

각 시험에서 처음 받은 전송 성공 응답을 센서 대기열에 반영하지 않아 재전송했다. 서버가 재전송 12건을 중복으로 판정했고, DB에는 각 키가 한 번씩만 남았다. K03의 관측 시각과 온도는 온도 곡선 API의 60개 원본 점과 일치했다.

## 원인과 후속 조치

1대 구성의 요청 실패는 사용 가능한 수집기가 0개가 되면서 발생했다. 센서의 디스크 대기열로 최종 기록은 복구할 수 있었지만, 조회는 수집기가 돌아올 때까지 실패했다. 두 번째 수집기를 두고 헬스 체크 결과로 라우팅하면 프로세스 1개 중단을 견딜 수 있다. 실제 운영에서는 호스트와 저장소 장애를 별도로 시험하고, 대기열의 가장 오래된 기록 나이도 경보에 포함한다.
